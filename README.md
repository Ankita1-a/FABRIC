# FABRIC: Federated Adaptive BiomedCLIP with Instance-level Clinical Prompts

We present FABRIC (Federated Adaptive BiomedCLIP with Instance-level Clinical prompts), an enhanced federated learning frame- work that extends FACMIC along four dimensions:replacing CLIP with BiomedCLIP for domain-aware feature extraction, substituting static text prompts with image-level clinical descriptions generated by Llama 3.2 via Ollama, adopting an asynchronous FL protocol where only two of three clients participate per round, and incorporating class-aware offline data augmentation.

# Notebook Walkthrough, Key Findings & Results

*(Appended summary — generated by going through every `.ipynb` in `FACMIC/`, their execution logs/outputs, `FINAL_REPORT.pdf`, and the saved `results/`, `results1/`, `outputs_*` artifacts, so that the repository is self-explanatory on GitHub without having to re-run anything.)*

## 1. What each notebook does

### A. Reproducing the FACMIC baseline

| Notebook | Purpose |
|---|---|
| `RUN_MAIN.ipynb` | Thin Colab driver that mounts Drive, installs OpenAI CLIP, and runs `REPRODUCE_FACMIC_WITH_ORIGINAL_HP_MAIN.py` — the original FACMIC federated training loop (CLIP backbone, static prompt `"a picture of a {class}"`, feature-attention module, LMMD domain adaptation, FedAVG) using the **hyperparameters shipped with the original FACMIC code** (LR = 5×10⁻⁵, 50 rounds). Saves per-round accuracy/balanced-accuracy logs as CSVs. |
| `RUN_MAIN_2.ipynb` | Same pipeline, but runs `REPRODUCE_FACMIC_WITH_OUR_HP_MAIN_2.py` with the **hyperparameters matched to the FABRIC setup** (LR = 1×10⁻³, 50 rounds, batch 32) so FACMIC and FABRIC can be compared like-for-like later. |
| `PLOT_FACMIC_RESULTS.ipynb` | Loads the `Global_Acc7*.csv` / `Global_bacc7*.csv` logs produced by the two runs above and plots ACC/BACC curves for both hyperparameter settings, printing the first/best/final epoch values used in the report's Table 2. |

### B. Prompt generation

| Notebook | Purpose |
|---|---|
| `PROMPT_GENERATION_USING_OLLAMA.ipynb` | Installs and serves **Ollama + Llama 3.2** locally in Colab and generates a per-image (class-conditioned) clinical-style radiology description for every image in the original Brain Tumor dataset (3,244 images across `client_0`–`client_3`). Output saved to `llm_prompts_1.json` — these become the *dynamic, instance-level* text prompts used in place of FACMIC's fixed prompt. |
| `PROMPT_GENERATION_USING_OLLAMA_AUGMENTED_DATASET.ipynb` | Same prompt-generation procedure repeated over the **augmented** dataset (9,335 images, see below), saved to `llm_prompts_augmented_dataset.json`. |

### C. FABRIC — the proposed method (BiomedCLIP + dynamic prompts)

| Notebook | Purpose |
|---|---|
| `FABRIC_TARGET0.ipynb` | Trains on `client_1, client_2, client_3`; `client_0` is the held-out unlabelled LMMD target / final test client. |
| `FABRIC_TARGET1.ipynb` | Trains on `client_0, client_2, client_3`; `client_1` held out as target/test. |
| `FABRIC_TARGET2.ipynb` | Trains on `client_0, client_1, client_3`; `client_2` held out as target/test. |
| `FABRIC_TARGET3.ipynb` | Trains on `client_0, client_1, client_2`; `client_3` held out as target/test. **This is the main experiment** (BiomedCLIP backbone + Llama-3.2-generated dynamic prompts + LMMD + synchronous FedAVG, 50 rounds, LR = 1×10⁻³). |

All four together implement a **Leave-One-Client-Out (LOCO)** evaluation: each client takes a turn as the unlabelled target/test domain while the other three train.

### D. Data augmentation experiment

| Notebook | Purpose |
|---|---|
| `FABRIC_DATA_AUGMENTATION_PIPELINE.ipynb` | Builds `data_augmented/BrainTumor/` from `data/BrainTumor/`. `client_0`–`client_2` (training clients) get 2 randomly-chosen augmentations per image (3 for the minority `no_tumor` class, to rebalance it) drawn from a pool of 10 MRI-appropriate transforms (flips, rotation, affine, zoom/crop, blur, brightness/contrast jitter, and combinations — no colour/hue changes, since MRI is greyscale). `client_3` (test client) is copied unchanged. |
| `FABRIC_AUGMENTED_DATA_EXPERIMENT.ipynb` | Re-runs the FABRIC_TARGET3 training/eval pipeline but reading from `data_augmented/` and `llm_prompts_augmented_dataset.json`, to measure the effect of class-aware augmentation on convergence speed and per-client balance. |

### E. Asynchronous federated learning experiment

| Notebook | Purpose |
|---|---|
| `FABRIC_ASYNCHRONOUS.ipynb` | Same FABRIC_TARGET3 setup, except only **2 of the 3 training clients are randomly sampled each round** (partial participation) instead of all 3, simulating clients that are intermittently offline/unavailable. Tracks how often each client is selected and aggregates with FedAVG over only the active clients each round. |

## 2. Key results

### 2.1 Reproduced FACMIC baseline (`client_3` test set, α = 0.9 Dirichlet split)

| Setting | Epoch 1 | Best | Final (Ep. 50) |
|---|---|---|---|
| Original HP (LR 5×10⁻⁵) — ACC | 62.69% | **80.71%** (ep. 27) | 79.19% |
| Original HP (LR 5×10⁻⁵) — BACC | 62.73% | **79.80%** (ep. 27) | 77.74% |
| Matched HP (LR 1×10⁻³) — ACC | 60.66% | **78.68%** (ep. 43) | 78.17% |
| Matched HP (LR 1×10⁻³) — BACC | 60.42% | **78.22%** (ep. 43) | 77.44% |

The matched-HP run converges later and to a slightly lower accuracy, indicating the CLIP-based FACMIC baseline is sensitive to the learning rate.

### 2.2 FABRIC vs. reproduced FACMIC (main experiment, target = `client_3`)

| Method | ACC (%) | BACC (%) | Best at |
|---|---|---|---|
| FACMIC (original HP) | 80.71 | 79.80 | Ep. 27 |
| FACMIC (matched HP) | 78.68 | 78.22 | Ep. 43 |
| **FABRIC (ours)** | **84.77** | **85.32** | Rd. 30 |
| Δ vs. original HP | **+4.06** | **+5.52** | — |
| Δ vs. matched HP | **+6.09** | **+7.10** | — |

Because the improvement over the *matched*-HP baseline is even larger than over the original HP, the gain is attributable to FABRIC's architectural changes (BiomedCLIP backbone + dynamic per-image prompts), not to hyperparameter differences.

### 2.3 Leave-One-Client-Out evaluation (`FABRIC_TARGET0`–`3`, synchronous FL)

| Test client | ACC (%) | BACC (%) | Best round |
|---|---|---|---|
| client_0 | 87.47 | 87.55 | 17 |
| client_1 | 88.71 | 88.61 | 4 |
| client_2 | 89.78 | 90.70 | 9 |
| client_3 | 84.77 | 85.32 | 30 |
| **Mean** | **87.68** | **88.05** | — |

FABRIC generalises consistently across all four clients (84.8%–89.8% ACC); `client_3` scores lowest, consistent with it having the smallest data partition.

### 2.4 Synchronous vs. asynchronous FL (`FABRIC_ASYNCHRONOUS.ipynb`, target = `client_3`)

| Protocol | Clients/round | ACC (%) | BACC (%) | Best round |
|---|---|---|---|---|
| Synchronous | 3/3 | 84.77 | 85.32 | 30 |
| Asynchronous | 2/3 | 84.01 | 84.50 | 47 |
| Δ | — | −0.76 | −0.82 | — |

Client participation over 50 rounds: `client_0` selected 34× (68%), `client_1` 29× (58%), `client_2` 37× (74%) — close to the expected 66.7% for uniform 2-of-3 sampling. Skipping one client per round cuts per-round communication by a third for only a ~0.8-point accuracy/BACC drop, at the cost of slower convergence (best round 47 vs. 30).

### 2.5 Effect of data augmentation (`FABRIC_AUGMENTED_DATA_EXPERIMENT.ipynb`, target = `client_3`)

| Setting | ACC (%) | BACC (%) | Best round |
|---|---|---|---|
| Sync, no augmentation | 84.77 | 85.32 | 30 |
| Sync, augmented | 84.52 | 85.04 | 10 |
| Δ | −0.25 | −0.28 | 20 rounds earlier |

Augmentation reaches essentially the same accuracy **20 rounds faster**, and per-client validation shows the biggest gain on the most data-starved client (`client_1`: 75.61% → 84.09% ACC, +8.48), confirming that class-aware augmentation helps most where non-iid imbalance is worst.

**Augmentation dataset stats** (`FABRIC_DATA_AUGMENTATION_PIPELINE.ipynb`): 3,244 original images → 6,091 augmented copies → **9,335 total** images in `data_augmented/BrainTumor/` (client_0: 1,476 → 4,631; client_1: 425 → 1,333; client_2: 949 → 2,977; client_3 copied unchanged: 394). The 10 transforms are used in roughly equal proportion (9.4%–10.5% each), confirming balanced random sampling.

**Prompt generation stats**: `PROMPT_GENERATION_USING_OLLAMA.ipynb` produced 3,244 dynamic prompts (`llm_prompts_1.json`); `PROMPT_GENERATION_USING_OLLAMA_AUGMENTED_DATASET.ipynb` produced 9,335 prompts for the augmented set (`llm_prompts_augmented_dataset.json`).

## 3. Key findings

- **BiomedCLIP + dynamic clinical prompts clearly beat CLIP + a static prompt.** FABRIC outperforms reproduced FACMIC by +4.06% ACC / +5.52% BACC (vs. original HP) and +6.09% ACC / +7.10% BACC (vs. matched HP) on the same `client_3` test split.
- **The improvement is architectural, not a hyperparameter artifact** — the gap over the *matched*-HP FACMIC baseline is larger than over the original-HP baseline.
- **BACC improves more than ACC in every comparison**, indicating FABRIC is especially effective at improving recall on the minority `no_tumor` class rather than just overall accuracy.
- **FABRIC generalises well under LOCO evaluation** (mean ACC 87.68%, mean BACC 88.05% across all 4 clients as test target), not just on the `client_3` split highlighted as the main experiment.
- **Asynchronous FL (2-of-3 clients/round) is a good communication/accuracy trade-off** — about a third less communication per round for under 1 point of ACC/BACC loss, with stable convergence.
- **Class-aware offline data augmentation accelerates convergence** (20 fewer rounds to reach comparable accuracy) and disproportionately helps the smallest/most imbalanced client, at a negligible (<0.3 point) cost to final accuracy.
